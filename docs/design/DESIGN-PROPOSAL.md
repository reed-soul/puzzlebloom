# 设计提案：从「一个安静的谜题页」到「一座会回应的花园」

状态：提案，等待取舍。范围：PuzzleBloom 第二阶段的整体设计——玩法、界面语言、交互流程。
前置条件：不新增依赖、不引入服务端、不破坏 `_headers` 里的 CSP 与四项承诺。

---

## 0. 一句话

玩法上补上「出题」这一层，视觉上把系统里唯一一次允许的「弹」扩展成受管的第二个声部，结构上让主页长出一座真的会长大的花园。

---

## 1. 诊断：现在这个站为什么不「好玩」

它安静、得体、可信，一个成年人会喜欢。但一个十岁的孩子不会主动再打开一次。原因不是不好看，是三处结构性缺失：

1. **没有「再来一次」的理由。** 一局棋结束，没有任何东西在等你。没有积累，没有下一样东西，也没有人知道你做过。
2. **没有能动的东西。** 全站只有一块棋盘可以点。孩子会戳的东西太少；戳了也大多没反应——落子是唯一的高光。
3. **没有「我」。** 主题工作室是唯一有作者感的地方，而它只管颜色。做完二十道题，站上没有任何痕迹。

第四个问题更隐蔽：**系统把「张力」和「噪音」一起删掉了。** 没有计时、没有连击、没有分数，所以也没有「差一点」的心跳。

`tokens.css` 里那句注释是对的——「Nothing here bounces or overshoots: this is a calm site.」这句是这套系统的品格，不是缺陷。但它解释了上面第 1、2 条：**一个从不回应的界面，很难让人觉得好玩。**

---

## 2. 设计立场：压力归玩家

系统拒绝的从来不是乐趣，是**别人替你决定的压力**。把这条说清楚，后面每个决定都能自检：

| 原来的话 | 真正的意思 |
| --- | --- |
| 没有计时器 | **没有你没要求的计时器。** 想要就给你一个，在你的手里。 |
| 没有连击 | **没有会断的连击。** |
| 没有排行榜 | **没有陌生人的排行榜。** 认识的人之间可以有。 |
| 没有账号 | **不需要账号也能全部玩完。** |

自检一句话：**任何会让孩子感到「我落后了」的元素，必须由他自己打开。**

「花园只长，不枯」是这个立场的具体形态——它是反 Duolingo 的：好东西可以累积，不做也不会失去。

---

## 3. 两个声部：quiet / play

现在全站只有一个速度。而 `pb-land` 那个 `scale(1.06)` 的过冲，是整个系统里唯一一次允许的「弹」——它被小心翼翼地只用在数字落格上。

设计上的核心动作不是发明新风格，是**把这一次「弹」提升成一个受管的第二声部**：

| | quiet（外壳） | play（桌面） |
| --- | --- | --- |
| 用在哪 | 导航、页面、路由转场、主题切换 | 棋盘、骰子、天平、落子、完成、出题徽章 |
| 曲线 | `--pb-ease` `cubic-bezier(.22,1,.36,1)` | `--pb-ease-play` `cubic-bezier(.34,1.56,.64,1)`，过冲 ≤ 6% |
| 时长 | 180 / 260 / 340 ms | 90 / 180 / 420 / 620 ms，**关键动作 90ms 起** |
| 幅度 | 位移 ≤ 10px、旋转 ≤ 4° | 缩放 ≤ 6%、旋转 ≤ 8°、位移 ≤ 24px |
| 颜色 | 只动 opacity / transform | 允许一次性的 accent 闪光 ≤ 220ms，**不许循环** |
| 声音 | 无 | 有，一次动作一个音 |

**跨声部不混。** 页面转场永远 quiet；棋盘内部永远 play；同一屏里两种曲线不同时跑。

这比「全部统一」更能保住一致性——一致性不是「所有东西一样慢」，是**「该慢的地方永远慢」**。孩子会觉得棋盘是活的，同时觉得这个网站是稳的。

新增 token（`tokens.css`，全部从现有 11 色派生，不新增颜色）：

```css
--pb-ease-play: cubic-bezier(0.34, 1.56, 0.64, 1);
--pb-dur-tap: 90ms;
--pb-dur-snap: 180ms;
--pb-dur-celebrate: 620ms;
--pb-lift-press: 0 1px 0 var(--pb-shadow);   /* 按下时硬边塌一半，像真的按下去 */
```

`--pb-lift-1` 那个「硬边 + 软影」的双层高度本来就是玩具的语汇，按下时让硬边从 2px 塌到 1px，是这套语言里最便宜的一次触觉。

### 3.1 声音

全站现在是静音的。对「好玩」而言，声音的性价比高于任何动画。

规则：WebAudio 现场合成，**不引入音频文件**（不进 bundle、不碰 CSP、不产生请求）。一次动作一个音，无背景音乐。

- 落子：一个短促的木质「嗒」——带通滤波的噪声爆发 + 20ms 衰减。
- 错误：同一个音低五度，音量 −6dB。**不刺耳，不吓人。**
- 完成：三音上行琶音，音高取自当前主题的 `brand` 色（色相 → 调性），所以换个主题连声音都会变。
- 默认开，静音键固定在游玩栏右侧；`localStorage` 记住；`AudioContext` 在第一次真实点击时才创建（浏览器要求，也符合「不主动出声」）。

## 4. 核心循环：四拍

每一拍都要能在屏幕上指出来，不能是「提升参与度」这种话。

**① 选（2 秒）** — 从卡片到可玩。桌面整块推上来，棋盘**已经在等**，不出现白屏或骨架屏。这一步的体验指标是：首帧可交互 < 1 秒（本地包，本来就该如此）。

**② 破（30 秒 – 5 分钟）** — 每一步 90ms 内有回应。乐趣来自**确定感**：对的落子要有「嗒」，错的要有「不」，而不是安静地什么都不发生。这是现在最缺的东西。

**③ 变（620ms，只发生一次）** — 三件事同时发生：完成的线扫过、棋盘轻抬 4px、花园里长出一株。**同一次「变」不超过 3 个动作。** 第四件就开始廉价了。

**④ 长（退出后仍然存在）** — 花园 +1，卡片上出现你自己的最好记录（只给你看）。这拍必须给出**下一个动作的对象**：「把这道题发给谁」或「出一道更难的」。没有第 4 拍，第 1 拍就会失效。

## 5. 旗舰玩法：出题（Make one）

### 5.1 为什么是它

解谜是消费，出题是创作。孩子愿意花在「让别人做不出来」上的时间，通常比解题更多。而且这是这个站**唯一能做、几乎所有同类站都没做**的事：所有 sudoku 站都让你解，几乎没有让你出。

它有现成的地基：`packages/sudoku-engine` 已经有解的数量统计，`packages/theme-core/src/share.ts` 已经有把数据压进 URL 的能力，`CreatureGlyph` 已经让六岁孩子不必认数字。**这不是新造一个游戏，是把已有的零件接上一条新回路。**

### 5.2 三层难度，同一套代码

| 层 | 年龄 | 玩家在做的事 | 平台的回应 |
| --- | --- | --- | --- |
| L1 | 6–8 | 摆一个「能解」的 4×4 | 徽章：无解 / 能解 |
| L2 | 9–12 | 摆一个「只有一个解」的 | 徽章三态翻转——**这是整个玩法的心跳** |
| L3 | 12–15 | 用更少的提示凑出唯一解 | 只显示「你用了 4 个提示」，不排名 |

L2 的那一跳是有教育价值的：孩子会自己发现，**随手画出来的格子绝大多数根本不算「题」**——多解、无解、或者空格太少。没有人告诉他，他自己撞出来。这比任何提示文案都有效。

L3 有真实的数学深度可以追：4×4 的下限是 4 个提示；9×9 目前已知是 17 个。一个十三岁的孩子会为了「能不能只用 5 个」耗掉半小时，而这条路**不需要我们写一行新关卡**——难度是涌现的，不是编排的。

### 5.3 交互细节（这些决定手感）

- **空格也参与判定。** 一道题 = 唯一解 + 至少 N 个空格。否则「全填满」也算唯一解，规则就漏了。
- **徽章颜色只用三支现有色**：`brand`（恰好一个解）/ `accent`（多个解）/ `danger`（无解）。不新增颜色，也就不会和主题打架。
- **算的时候不要抖。** 每次改动后 120ms 防抖再判定；判定中徽章不闪烁、不转圈，只做一次 200ms 的 opacity 呼吸。孩子最怕的就是界面一直在「算」。
- **状态不能只靠颜色**：徽章要同时有图标与一句话（「只有一个答案」/「有不止一个答案」/「无解」）。这条是硬性的，见 §10。
- **出题完成 = 一句可复制的东西。** 链接里只装题目和昵称，不装任何身份信息。

### 5.4 社交闭环（安全的那种）

```
出题 → #make/sudoku（本地）→ 一句链接 ?p=<base64url>
     → 朋友打开 → 解 → 得到「回执」链接
     → 原出题人打开回执 → 看到「解开了，用了 6 分 12 秒」+ 一步也没提示
```

关键在于：**全程没有一个陌生人，也没有一个服务器。** 全站现在没有一个 `connect-src` 之外的外部请求，这条设计不需要破例。这是「没有排行榜」和「想和朋友比」之间唯一的正解。

## 6. 花园

- 每个游戏一个物种：sudoku = 蕨类，balance = 蘑菇，tangram = 石头。物种由游戏 manifest 的 `tone` 派生，不新增配色。
- 权重是有立场的：**解一题 +1，出一题 +2。** 出题比解题值钱，因为我们想鼓励的是后者。
- **只长不枯。** 没有连续天数，没有枯死，没有「你已三天没来」。
- 位置在主页第二屏，通栏。它是**全站唯一允许持续缓慢运动的装饰**，而且是复用 `pb-sun-turn` 那 40 秒的节奏——不新增第二个节奏。
- 存 `localStorage`，可导出成一张 PNG，可一键清空。清空要两次确认，因为这是孩子在站上唯一的「作品」。

## 7. 站点结构

```
/                 主页：立刻能玩的一块 → 花园 → 货架 → 承诺 → 主题
/play/sudoku      棋桌
/make/sudoku      出题台
/play/*           其余游戏，同一套棋桌壳
/themes           主题工作室（已有）
/parents          给大人的说明（已有）
```

三处改动建议：

1. **卡片必须回答三个问题**：现在能不能玩 / 多久能玩完 / 有多难。前两个现在有，第三个没有。
2. **难度用刻度，不用星。** 1–5 个实心点，点少的是浅的。星是评价语汇，刻度是状态语汇——这个站不需要评价。
3. **「生长中」的卡片不能只是灰的。** 灰卡片告诉孩子「这里没东西」。给一个能真的动一下的 30 秒样本（nonogram 只给 5×5 的一行），成本不高，但它把「还没做」变成了「正在长」。

## 8. 状态与失败

好路径谁都会写，这里只列会被孩子撞到的边角。

- **错三次不惩罚，换一种说法。** 沿用现有 hint 的语气：不是「再试一次」，而是「这一格其实只剩两个可能，另一个是 7，为什么不是它？」
- **无路可走时直接说。** 求解器能证明当前局面无解，就不要让孩子继续耗——告诉他，并给「退回上一处」，而不是「重新开始」。
- **随时可以走，不弹确认。** 「你确定要离开吗」是挽留，也是压力。
- **回来要回到原来的地方。** 目前刷新即丢局面——这是 P0，比任何新玩法都优先。
- **空白状态也要好看。** 花园第一次打开是空的，那一屏决定他会不会再回来。

## 9. 一致性红线（明确不许加）

这些不是审美偏好，是这套系统能自洽的原因：

- 不许加：连续天数、陌生人排行榜、推送、弹窗奖励、开箱、限时活动、红点。
- 不许加：第三种字体、第二种圆角语言、第十三种颜色。
- 不许加：emoji 当图标（`icons.tsx` 里已经写明三条理由：各平台渲染不同、吃不到主题色、读屏会念出 Unicode 名）。
- 不许加：全页视差滚动。花园是唯一允许「持续运动」的地方，唯一。
- **不许在两个声部之间混。** 这条最容易在赶工时破。

## 10. 怎么知道它成立（可验证，不是感觉）

- **首局到第一步 < 15 秒**（Playwright，从 `goto` 到第一次落子）。
- **没有死路**：随机点击 200 个可点元素，任意状态下都有可见反馈，无 console error。
- **判定正确性**：200 个随机 4×4 网格的「解的数量」与暴力枚举逐一对齐（单元测试，复用现有 test 风格）。
- **无障碍**：全键盘可玩；`prefers-reduced-motion` 下 play 声部时长归零，但**状态色与文案变化必须保留**——信息不能只靠动效传达。
- **声部隔离**：一次路由切换期间，不得出现 `--pb-ease-play` 的曲线（可在 E2E 里断言 computed style）。

## 11. 工程切分（按可独立上线的顺序）

| 顺序 | 内容 | 依赖 | 为什么这个顺序 |
| --- | --- | --- | --- |
| 1 | 局面持久化 | 无 | 最小改动，体验提升最大 |
| 2 | play 声部 + 声音 | theme-core | 整个「好玩」的地基 |
| 3 | 出题台 `/make/sudoku` | sudoku-engine | 旗舰玩法，且能复用 share.ts |
| 4 | 花园 `/garden` + 主页通栏 | localStorage | 让第 3 步有去处 |
| 5 | 回执链接 | share.ts | 社交闭环，纯数据 |

每一步都能单独发布，也都能单独回滚。**不要一次做完。**

## 12. 一个可玩的样机

`docs/design/prototype.html` 是旗舰玩法的 L1/L2 最小可玩版本：4×4、点击摆子、实时判定解的数量、出题后生成一句可复制的题目串、再切到解题模式把它解开。

它刻意做得很小——只为了验证三件事：徽章翻转的那一下是不是真的有意思；90ms 的手感对不对；以及「随手摆的格子多半不是题」这个发现会不会自己冒出来。**看代码没有意义，去点它。**

样机故意欠下的三笔账，正式实现时不要照抄：

1. **它每次操作都重建整块棋盘。** 于是所有格子的落子动画会一起重播——这也是为什么在 200ms 的那一刻截图，整盘生物是半透明的。正式实现必须按格 diff，只让**变化的那一格**跑 `pb-land`。这条在原型里看起来像美术问题，其实是渲染策略问题，改样式改不掉。
2. **它没有做 `prefers-reduced-motion` 的信息补偿。** 样机只是把时长压到 0.01ms。正式实现里，状态的变化必须落在颜色与文案上，动效只是加强。
3. **它把 4×4 的判定写死在页面里。** 正式实现应当直接用 `packages/sudoku-engine` 的解计数，并把样机里这套 `countSolutions` 当成一份对照测试的期望值。
