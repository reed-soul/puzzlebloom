## 新增第二个成品游戏：Nonogram（数织）

用户报"现在做了几个游戏了？"，答：1 个成品（Sudoku）+ 3 个只登记未开工（Nonogram / Memory Garden / Tangram）。用户说"一个一个做吧"，于是按 registry 顺序先做 Nonogram。

### 交付内容

- `packages/nonogram-engine`（新）：8 张手绘位图（4×5×5 + 4×10×10），线索生成，`solveLine`（位置 DP）+ `solveLineByExhaustion`（2ⁿ 参考实现，仅测试对拍），`solveByLogic` 传播求解器，`nextHint` 讲解式提示，`dailyPuzzle`（FNV-1a + mulberry32，不用 Math.random），`progress` RLE 序列化（`pb.nonogram.progress.v1`）。69 个单测。
- `games/nonogram`（新）：Fill/Cross 双模式、pointer capture 拖拽（一次笔画一次历史）、全键盘可解、线索条完成态、胜利揭示图。
- 站点接入 5 处暗缝：`registry.ts`、`App.tsx`、`site.json`、`app/head.ts`（结构化数据泛化成每路由一个 WebApplication）、`Home.tsx`（按 status 分支 + 卡片 art 由 manifest 决定 + 数量驱动的文案）。
- 根 `package.json` 的 test 脚本串入新引擎。

### 关键设计决定

1. **谜题从图反推线索，不随机挖空**。保证有解、解唯一、填完必成画；代价是只能设计画不能设计题。
2. **DP 而非枚举**。10×10 上枚举能跑但复杂度随尺寸指数增长；DP 是 O(n·k)，代价是无法目视验算，所以参考实现留在包里做对拍。这条抓到 3 个真 bug。
3. **Fill/Cross 双模式**而非三态循环。手机上叉号是主体操作，循环三态要为划掉一格点两次。
4. **共享模态行为落在 `packages/ui/useModalFocus`**，因为 `games/` 之间只允许 type-only 依赖；且"模态该有什么行为"必须只有一个定义。

### 焦点缺陷（本次唯一的返工）

QA 实测：胜利面板鼠标路径焦点回到棋盘按钮、落在 `aria-modal` 弹窗背后。机械原因：React 在 pointerdown 离散事件里同步 flush effect 把焦点给卡片，随后浏览器 mousedown 默认聚焦又拿回去。

修法：`useModalFocus` 双机制——指针路径靠捕获相 `focusin` 兜底（0.2ms 内修正），键盘路径靠 `requestAnimationFrame`（没有 focus 事件可抓）。两条路径各需一条机制，删任一条会挂掉一条路径。

WebKit 追加两条：Tab 无条件 `preventDefault` 自管（Safari 默认顺序导航跳过按钮，会让焦点掉到 `<body>`）；归还焦点也推一帧（浏览器删除聚焦元素后的焦点修复发生在我们的 `focus()` 之后）。

同时补了数独的胜利面板（原本从不移动焦点，比 nonogram 更差）与两处暂停帘幕（`aria-modal`）。

### 未决

## 新增第三个成品游戏：Tangram（七巧板）

用户"一个一个做吧"的第二个。图集难度高于预期，交付分两轮：引擎/游戏/站点接入一轮，图形集返工一轮。

### 交付内容

- `packages/tangram-engine`（新）：七块规范多边形与变换（`fromPolygon` 反解质心/旋转）、六张图、光栅化覆盖率判定（`checkFigure`，步长 0.02、容差 0.4%）、`snapPlacement` / `snapOnNudge`、可解释提示、每日题、进度序列化（`pb.tangram.progress.v1`）、零 import 的 `card.ts`（首页卡面数据）。70 个单测。
- `games/tangram`（新）：SVG 棋盘、托盘、指针拖拽 + 顶点吸附、45° 离散旋转、翻转、全键盘可解（方向键 + R/F + 吸附）、一次拖动一次撤销、胜利面板复用 `useModalFocus`。
- 站点接入同 nonogram 的九处接缝；`site.json` 现 6 条路由，首页 3 张 ready 卡。

### 关键设计决定

1. **判定比对覆盖率，不比对答案**。七巧板图形普遍多解（两块大三角可互换），逐块比坐标会把正确答案判错。由面积恒等式，"每处覆盖恰好一次"已蕴含"无重叠"。
2. **剪影由作者的摆法自己长出来**，不另画一份——"图长什么样"和"赢了是什么意思"由同一份数据推出。
3. **旋转离散到 1/8 圈，位移靠顶点吸附**。图形坐标含 √2，网格对齐会与正确答案打架。
4. **图集多样性写成断言**（`cores.test.ts`）。初版六张图有 **5 张共用同一个五小块骨架**——测试全绿、功能正确，但谜题实际只有一个。这是只有人读坐标才能看出来的问题。

### 返工与遗憾

`house` / `boat` 被删除：这两个轮廓在几何上只有唯一一种铺法（就是那个共用骨架），换骨架只能换轮廓。替换为 `sail`（直角三角形）与 `step`（L 形）。代价是图集偏几何、少了几分可爱——用"六道不同的题"换的。

### 验收基线

lint 154 files clean / typecheck clean / 单测 370（189+70+69+42）/ build:seo 6 routes PASS / e2e **120 tests：119 passed、1 skipped**（仅 CDP 监听计数那条 Chromium 专属）。

### 修掉的真 bug

- 拖动落子后第一次 Undo 空操作（历史压的是"松手那一刻"）。
- 首页卡片画着已被删除的 `house`（手抄坐标漂移）→ 改成从引擎派生。
- `Parents.tsx` 的"清除所有数据"只删 `pb:` 前缀，而游戏键是 `pb.*`——这个按钮从来没清掉过任何游戏进度。

## 新增第四个成品游戏：Memory Garden（记忆花园）——花园完工

用户"一个一个做吧"的最后一个。`SPROUTING` 已清空，站点从"1 个成品 + 3 个待发芽"走到"4 个成品"。

### 交付内容

- `packages/memory-garden-engine`（新）：九只生物、按种子的发牌（Fisher–Yates + mulberry32）、翻牌状态机、复盘（最长连对 / 最常错配的一对）、只复述玩家已见卡片的提示、每日牌局、进度存档。61 个单测（QA 补了 14 个）。
- `games/memory-garden`（新）：翻牌网格、三档 6/8/9 对、roving tabindex 键盘操作、错配不自动回翻、胜利面板复用 `useModalFocus`。
- 站点：7 条路由、4 张 ready 卡、0 张待发芽；首页栏头换成 "…The garden is full for now."

### 两个立住这个游戏的设计

1. **错配的两张牌不自动翻回去**，一直亮着直到玩家翻下一张。理由：定时回翻对读得慢的人是欺负，而且把"我记住了吗"偷换成"我手快不快"。
2. **结束时给复盘**，三条由回合日志算出的事实（回合数 / 最长连对 / 最常错配的一对）。这是记忆游戏唯一能"解释"的东西——不是你错了，是你的注意力被什么绊住了。

### 关键决定

- **牌数上限 9 对**：花园只有九只生物，一对就是同一只的两张。禁止"同一只出现四次凑大盘"，那会让"记住位置"退化成"记住哪几张同款"。
- **提示只报行不报列**（我拍的板）。报列等于指出答案；只报行仍是玩家自己走一步。四个游戏的提示守同一条线。
- **`seen` 不落盘**，从回合日志 + 当前亮着的牌反推，存档只存 `faces + log + seed`，牌面由发牌重算——不存在第二份真相会分叉。
- 九只生物里有三个字形不像动物（尖角 / 三个圆点 / 锯齿冠），工程师拒绝硬安动物名（"the horned one / the spotted one / the crowned one"），名字变成对造型的描述而不是第二件要记的事。

### 验收

QA 做了四条变异验证（把错配分支改成自动回翻、`bestRun` 改成总数、删掉提示的 `seen` 过滤、牌数上限放到 10），四条**全部变红**——没有一条测试是假装在守承诺。主理人独立复跑五条命令一致。

lint 178 files / typecheck clean / 单测 431（189+69+70+61+42）/ build:seo 7 routes PASS / e2e **144 tests：143 passed、1 skipped**（仅 CDP 监听计数）。

### 已知残余

- WebKit 的原生 Tab 序不经过按钮（引擎级特性，`useModalFocus` 存在的原因）；真机 Safari 需人工确认一次 Pause/Hint 是否可达（H 有快捷键，Pause 没有）。
- 提示只报行，两只同类同在首行时指向不唯一——但任翻一张都对，不构成误导。

## 调研 img2threejs（外部项目评估，未动代码）

结论：**不采用，且示例站的游戏拿不过来。**
- 核心仓库 `img2threejs/img2threejs` = Apache-2.0，但只有流水线（forge/ 90 个 Python 脚本 + grimoire/ 门禁文档），**不含任何 demo 代码**。实测 `forge/plugins` 不存在，全仓搜不到 THREE.Group 产物。
- 示例站内容在**另一个仓库** `img2threejs-showcase`（857MB，克隆确认）：**没有 LICENSE 文件**，全仓唯一 license 字样是 `index.html:139` 的 JSON-LD 指回核心仓库的 LICENSE，不构成对 showcase 自身代码/素材的再许可。默认 = 保留所有权利 = 不可复制。CONTRIBUTING 只要求投稿者自证参考图有权使用，没有任何出向授权。
- 示例站 33 个条目里只有 3 个真游戏（skybound-adventure 像素平台 ~2776 行 TS + 大量切图、greenvale PixiJS 探索 7147 行、snowy-village 雪村小游戏 3135 行），其余 30 个是可轨道旋转/拆部件/读源码的模型展厅。选题大量是第三方 IP（CS2 的 AWP/Talon/Glock/M9/Classic、Lee Sin、Groot、皮卡丘、哆啦A梦、王国之心 Sora），IP 本身也不属于他们。
- 技术栈 `three@0.169 + pixi.js@8.22 + three-mesh-bvh + meshoptimizer`。对照本项目 `apps/web` 的依赖只有 react/react-dom，dist 最大 chunk 214K、全站产物 2.1M —— 一个最小 three 场景树摇后约 150K gzip，等于再塞一个 React 进去。
- 产品线也不匹配：本项目七个游戏都是"从确定解反推问题"的确定性逻辑谜题，Skybound 是实时平台跳跃，资产重心是 sprite 表与手感调参，两套东西共站会把"零运行时依赖 + 可预渲染 + 跨游戏 type-only 依赖"这三个优势变成负担。

**唯一值得借鉴的是方法论**（Apache-2.0，可合法读）："Scripts enforce, the model judges"、细节清单不完整则阻断生成、每轮审查只看一张归一化的对比图、"达不到要求保真度是合法结果"。与现有"暴力参考实现对拍 / 故意改坏判定器 / 断言的地理位置会骗人"是同一族信仰。

顺带确认：`apps/web/src/games/registry.ts` 现在已有 **7 个**游戏（sudoku/nonogram/tangram/memory-garden/balance/frog-road/bloom），`SPROUTING` 仍为空——项目记忆里"4 个游戏"已过期。
