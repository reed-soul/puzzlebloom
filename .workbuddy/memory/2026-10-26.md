## test 链改成可发现（A）

根 `package.json` 的 `test` 从手写五连串改成：

```
pnpm -r --filter "./packages/*" --filter "./games/*" --if-present test
```

`--if-present` 是必需的：`packages/ui` 与七个 `games/*` 都没有 `test` 脚本，不加这个标志递归会失败。

改的原因：手写链漏了三个引擎。改动前 `balance-engine` / `bloom-engine` / `frog-road-engine` 的测试**从来没在 `pnpm verify` 里跑过**（它们各自有 `test: vitest run` 和测试文件）。改后 8 个套件全跑，464 个测试通过：sudoku 189、nonogram 69、memory-garden 61、tangram 70、theme-core 42、balance 16、bloom 9、frog-road 8。

## check-artifact 增加 canvas 断言（B）

`scripts/check-artifact.mjs` 新增：路由 HTML 里出现 `<canvas>` 时，
1. `<canvas>` 必须有 `aria-label` / `aria-labelledby` / `aria-hidden="true"`；
2. canvas 之外的可读文本（剥掉 script/style/svg/canvas 再剥标签）必须 ≥ `CANVAS_TEXT_FLOOR`（200 字符）。

设计上选择**从产物自动探测**而不是在 `site.json` 加 `canvas: true` 字段——加字段等于又一份要记得维护的手写清单。

负例验过了（三种情况各跑一遍）：裸 canvas → 报可访问名；`aria-label` 齐全的正常页面 → PASS；只有 h1 + canvas 的页面 → 报 68 字符不足。正向用例在真实产物上仍 PASS，10 条路由无误报。

## 下一步（C，three.js 游戏）的已知接缝

用户确认目标栈是 three.js。九个接缝里真正会疼的是第 0 条：**主题下发机制对 canvas 失效**。`applyTheme()` 把 11 个 `--pb-*` 变量写到 `<html>` 上，2D 游戏通过 CSS 免费拿到颜色；canvas 拿不到。React 侧的 `useTheme()` 在 `apps/web/src/app/ThemeProvider.tsx`，游戏包引用它会形成 `games → apps/web` 反向依赖。迁移成本很小：3 个引用点（`App.tsx` / `pages/Themes.tsx` / `pages/Home.tsx`），都在 `apps/web` 内部；Provider 移到 `packages/ui` 即可，代价是多一条 `ui → theme-core` 的向下依赖。

另外三个：预渲染等的是 `.pb-play` 选择器（10s 超时）且会 abort `**/*worker*.js`，所以游戏外壳 DOM 不能等 three 加载完成；e2e 的 mobile project 是 iPhone 17 Pro / WebKit，而 WebKit 的 headless WebGL 是最不稳的，但按项目自己的理由（目标设备是 iPhone）不能把它排除掉；CSP 不用改（`script-src 'self'` + `worker-src 'self' blob:` 够用，除非引 wasm 模块）。

## 第 0 步：ThemeProvider 迁到 packages/ui

动因：three.js 游戏需要真实色值，而 `useTheme()` 原本在 `apps/web/src/app/ThemeProvider.tsx`，游戏包 import 会形成 `games → apps/web` 反向依赖。

做法（**走子路径导出，不走 barrel**——七个游戏都依赖 `@puzzlebloom/ui`，往 `index.ts` 加会把 theme-core 拖进每个游戏 chunk）：
- 新增 `packages/ui/src/theme.tsx`（原 `ThemeProvider.tsx` 平移，仅改文档头说明为什么在这）
- 新增 `packages/ui/src/viewTransition.ts`（原 `apps/web/src/app/viewTransition.ts` 平移；router 与主题切换共用）
- `packages/ui/package.json`：exports 加 `"./theme"` / `"./transition"`；dependencies 加 `@puzzlebloom/theme-core: workspace:*`；devDependencies 补 `react-dom` + `@types/react-dom`（`withViewTransition` 用 `flushSync`，ui 原来只有 react）
- 删除 `apps/web/src/app/ThemeProvider.tsx` 与 `viewTransition.ts`
- 4 个 import 改动：`App.tsx`（ThemeProvider）、`pages/Themes.tsx`、`pages/Home.tsx`（useTheme）、`app/router.tsx`（withViewTransition）
- `pnpm install --config.engine-strict=false`：lockfile +4 行，`packages/ui/node_modules/@puzzlebloom/theme-core` 软链建立

验证：typecheck 0、lint 对 9 个改动文件 0、`pnpm test` 8 套件全绿（bloom 已由用户改成 12 个）、build + 10 路由预渲染 + check-artifact PASS、`theme.spec.ts` + `balance-canvas.spec.ts` 共 20 个 e2e 全过（含"换 mood 重绘"与"保存后刷新仍在"）。chunk 体积无变化（index 64.36 → 64.37 kB）。

### 两个修正（上一轮的判断有误）

1. **`balance` 和 `bloom` 已经是画布游戏**，用 HTML-in-Canvas（`content="drawable"`，见 `games/balance/src/useHtmlInCanvas.ts`，探测失败则退回 DOM 版）。所以"canvas 拿不到 CSS 变量"不能一概而论：它们画的是真实 DOM，天然继承 `--pb-*`。只有 WebGL 那条路才必须拿色值。
2. **B 的 canvas 断言对这两个游戏其实不会触发**——预渲染的 Chromium 里 `canvas.content !== 'drawable'`，走的是 DOM 回退分支，产物 HTML 里没有 `<canvas>`。所以 B 目前只覆盖"JSX 里同步渲染 `<canvas>`"这一种情况。要真正咬住这两个游戏，得在 e2e 阶段对活 DOM 断言，不是在产物上。

## Bloom 落点 bug：物理罐子一直是整个舞台

agy 3 分钟就抓到的真 bug：方向键按到最左，生物落在罐口外的花丛上。
根因不是 clamp 漏了，而是 `JAR` 只有 `width/height`（340×440 = 舞台），而画出来的玻璃只有
中间 ~164×230（`jar-scene.webp` 在 340×440 cover 下的实测）。所以墙、地板、罐口全都偏大：
生物会落在花丛/罐底以下，"满了"的判定也要堆到舞台顶（-8）才触发，视觉上早已溢出罐口。

修法（引擎只改边界，渲染坐标不动）：
- `JAR = { width, height, mouth:{left:104,right:237}, inside:{left:88,right:252,top:138,bottom:368} }`
- `aim` 夹到 mouth（投放必须穿过罐口）；`contain` 夹到 inside（合并出的大生物可用整个瓶身）；
  `drop` 的下一颗按新 tier 重新夹一次
- 溢出改为"顶部越过罐口 + |vy| < 2.5 连续 45 tick"——落体经过罐口不算，静止堆过罐口才算
- CSS 的虚线满罐线也挪到罐口（31.36% / 30.59% / 39.12%），不再横穿整张舞台
- 回归：引擎 12 条（新增远左落点、单颗经过罐口不判负、下一颗重新夹）；e2e 新增
  "边缘落点中心必须在舞台 30%–70% 且落到下半部"；全量 190 passed / 2 skipped

**没上线**：工作区里有一组并行的 ThemeProvider→packages/ui 重构未提交（App/router/pages/ui/check-artifact），
不想把别人的改动一起带上线。Bloom 修复本身已本地验证通过，等用户确认后单独发。

可视化评审页的坑：`present_files` 只有 HTML 会弹预览；图片要 base64 内嵌才自包含；
但 PNG 内嵌会到 500KB+，先转 JPEG q80 再嵌（~290KB）。宽截图用 `aspect-ratio` 统一，
竖图（手机、stage）必须单独给 `portrait/square` 类，否则 `object-fit: cover` 会把关键区域裁掉。
